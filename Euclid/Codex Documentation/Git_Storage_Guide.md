## Running the affected tools

The DR1 full builder already requires `--output-dir`; use the archive location
in [the full-manifest guide](DR1_Full_Manifest_Guide.md). Query evidence stays
beside its tables so the existing resume/hash checks can work. Never use the
source folder as its output directory. Existing `SHA256.json` is retained
unchanged as historical provenance; source files have since been edited.

Masking validation scripts now resolve the configured research folder through
`machine_paths.py` and fail if it is unavailable. Existing historical validation
paths in older reports refer to the relocated tree. The adoption report writer
reads its large JSON from the corresponding research archive path.

The three old artifact builders under `outputs/tesla-20261007`,
`outputs/galaxy-population-20261011` and
`Foreground Masking/MER_VIS_summary_build` retain their installed dependencies
locally. `@oai/artifact-tool` is a private runtime package, not a verified public
npm install. Fresh-machine regeneration requires a compatible Codex artifact
runtime; copying the source alone does not provide that runtime. Existing
builder-specific runtime paths and output behavior were not modernised here.

Older Word catalogues and exported reports are historical snapshots, including
the previous full-manifest/folder guides. Use this Markdown guide and the
updated Markdown guides for current data paths; those binary reports have not
been regenerated by this storage cleanup.

## GitHub limits and history

[GitHub's large-file guidance](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)
states that files above 100 MiB are blocked and repositories should ideally be
below 1 GB, with below 5 GB strongly recommended. These recommendations are
not a personal account storage quota. This task did not inspect billing or LFS
entitlements. Keeping generated results in Dropbox avoids adding an LFS storage
dependency for this project.

Deleting a large file in a later commit does not remove it from earlier commits.
Only the two unpublished commits are being rebuilt, preserving the already
published `origin/main` history. Previously published libraries and data remain
in that older history, so this cleanup does not shrink existing clones or fully
purge GitHub storage. No published-history rewrite or force push is needed.

Before committing future results, inspect `git diff --cached --stat` and check
tracked files above 20 MB. `.gitignore` excludes the known relocated data and
installed packages; it cannot impose a general file-size limit.
